# Intelligence

Коллекция навыков для AI агента: работа с Git и GitHub, постановка целей и создание новых навыков по стандарту Agent Skills. Каждый навык содержит инструкции в `SKILL.md` и при необходимости дополнительные материалы в `references/` или `assets/`.

## Каталог навыков

| Навык | Назначение |
| --- | --- |
| [create-branch](skills/create-branch/SKILL.md) | Создать Git-ветку и переключиться на неё, выбрав имя по соглашению проекта. |
| [create-commit](skills/create-commit/SKILL.md) | Подготовить и создать коммит с сообщением по Conventional Commits. |
| [git-push](skills/git-push/SKILL.md) | Отправить текущую ветку и готовые коммиты в удалённый репозиторий. |
| [create-pr](skills/create-pr/SKILL.md) | Найти существующий или создать новый GitHub pull request для отправленной ветки. |
| [git-send-changes](skills/git-send-changes/SKILL.md) | Выполнить полный процесс: подготовить ветку, создать коммит, отправить изменения и открыть PR. |
| [create-skill](skills/create-skill/SKILL.md) | Создать навык по документации Agent Skills и проверить его структуру и инструкции. |
| [smart-goals](skills/smart-goals/SKILL.md) | Составить рабочую цель из намерения или разобрать готовую цель по SMART в трактовке Дорана. |

## Подключение

Для локального подключения навыков разные AI-агенты используют распространённое межклиентское соглашение:

- `~/.agents/skills/` — навыки пользователя, доступные в разных проектах.
- `<project>/.agents/skills/` — навыки конкретного проекта.

Спецификация Agent Skills не требует конкретного расположения каталогов. Поддержка этих путей и символических ссылок зависит от агента; общий подход описан в [рекомендациях Agent Skills](https://agentskills.io/client-implementation/adding-skills-support).

Если агент поддерживает символические ссылки, подключите нужные каталоги из `skills/`. Например, из корня этого репозитория можно подключить `create-branch` для текущего пользователя:

```bash
mkdir -p ~/.agents/skills
ln -s "$(pwd)/skills/create-branch" ~/.agents/skills/create-branch
```

Ссылка использует исходные файлы репозитория: их изменения доступны без повторного копирования. После перемещения репозитория ссылку потребуется обновить.

Для `git-send-changes` также подключите `create-branch`, `create-commit`, `git-push` и `create-pr`: он обращается к их инструкциям по относительным ссылкам. Сохраняйте имена каталогов и размещайте их рядом.

Codex поддерживает указанные пути и символические ссылки на каталоги навыков. Сам каталог `skills/` этого репозитория не является стандартным путём обнаружения навыков Codex. После подключения Codex обнаруживает навыки автоматически; если они не появились, перезапустите его. Подробнее — в [документации Codex](https://learn.chatgpt.com/docs/build-skills).

### Требования

- Для Git-навыков нужен установленный Git и локальный Git-репозиторий.
- Для отправки изменений нужен доступ к соответствующему удалённому репозиторию.
- Для `create-pr` и полного процесса `git-send-changes` нужен GitHub CLI (`gh`) с настроенной авторизацией в GitHub.
- Для `create-skill` и `create-commit` нужен доступ к документации, указанной в их справочных материалах.

## Использование

Опишите задачу обычным запросом — агент может выбрать навык по его описанию. В Codex CLI и расширении для IDE навык также можно указать явно через `$имя-навыка`.

Примеры запросов:

```text
Создай ветку для добавления README.
Сделай коммит с изменениями документации.
Запушь текущую ветку.
Создай PR для отправленной ветки.
Закоммить, запушь и создай PR с изменениями документации.
Создай навык для проверки относительных ссылок в Markdown.
Помоги сформулировать рабочую цель из намерения: улучшить документацию для новых разработчиков.
Проверь цель в приложенном файле по SMART и предложи исправленную формулировку.
```

Отдельные Git-навыки выполняют свои операции: `create-commit` создаёт коммит, `git-push` отправляет готовые коммиты, `create-pr` работает с PR для уже отправленной ветки.

Для всего процесса используйте `git-send-changes`. Он продолжает рабочую ветку только для той же задачи, если связанный PR не завершён; наличие открытого PR не обязательно. Для новой задачи, с базовой ветки или после завершённого PR создаёт новую ветку от актуальной целевой базы. При неоднозначности уточняет выбор до коммита и отправки. Проверяет все коммиты и diff будущего PR, выполняет push и возвращает существующий PR или создаёт новый. Старые ветки и PR автоматически не удаляет. Обычная просьба изменить файл сама по себе не запускает отправку изменений.

При самостоятельном вызове `create-branch` базой по умолчанию остаётся текущий HEAD. Скил проверяет занятость имени локально и на выбранном remote и создаёт ветку без наследования upstream базовой ветки. При полном процессе отправки `git-send-changes` передаёт актуальную базу явно.
