# Создание pull request

Первая версия работает с GitHub через `gh`. Если CLI, авторизация или поддерживаемый хостинг недоступны, сообщи ограничение.

1. Определи исходную ветку и её репозиторий по запросу, upstream и remotes; целевой репозиторий — по запросу и контексту проекта, учитывая fork. При неоднозначности уточни назначение. При detached HEAD без явно указанной исходной ветки остановись.
2. Определи базовую ветку: явная база пользователя имеет приоритет, иначе используй default branch целевого репозитория. Проверь существование исходной и базовой веток. Если локальные коммиты ещё не отправлены, сообщи об этом; используй [git-push](../git-push/SKILL.md) только при уже имеющемся запросе на отправку. Сам запрос на PR не означает разрешение на push.
3. Найди открытый PR в целевом репозитории через `gh pr list --repo <repository> --state open --head <branch> --json number,url,baseRefName,headRefName,headRepository,headRepositoryOwner,isDraft`. Сопоставляй исходный репозиторий и ветку, а не только имя ветки. Если пользователь явно задал базу, учитывай её. При нескольких подходящих PR уточни выбор.
4. Если PR уже существует, верни его ссылку. Не создавай дубликат и не меняй автоматически описание, базу или статус draft/ready.
5. Для нового PR изучи все коммиты и diff исходной ветки относительно базы, а не только последний коммит. Если разницы нет, сообщи об этом без создания PR. Составь заголовок и описание по итоговым изменениям и шаблону репозитория; укажи выполненные проверки и их ограничения, не выдавая запланированные проверки за выполненные.
6. Создай обычный PR через `gh pr create --repo <repository> --base <base> --head <head> --title <title> --body-file <file>`. Для fork укажи владельца в head, где это поддерживается CLI. Draft создавай только по просьбе пользователя. Точный текст описания сохрани во временный файл с настоящими переводами строк; избегай shell-подстановок в пользовательском тексте.
7. Проверь созданный PR через `gh pr view` и сообщи ссылку, исходную и базовую ветки, а также статус draft/ready.

При ошибке сообщи причину. Если неизвестно, был ли PR создан, повтори поиск перед новой попыткой создания. Не выполняй merge, назначение reviewers или другие изменения PR без соответствующего запроса.
