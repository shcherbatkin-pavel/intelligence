# Создание ветки

1. Прочитай [references/branch-naming.md](references/branch-naming.md). Если пользователь задал имя ветки, используй его без переименования; иначе выбери имя по соглашению для задачи пользователя.
2. Проверь допустимость имени через `git check-ref-format --branch`.
3. Проверь, существует ли локальная ветка с выбранным именем. Определи remote для будущей отправки: явно заданный имеет приоритет, иначе используй remote upstream текущей ветки, затем `origin`, если он существует. При нескольких неоднозначных кандидатах уточни выбор. Если remote выбран, проверь наличие одноимённой ветки через `git ls-remote --heads <remote> refs/heads/<name>`. При ошибке проверки остановись; не считай имя свободным. Если remote не настроен, достаточно локальной проверки. Если имя занято локально или на выбранном remote, сообщи об этом и не перезаписывай существующую ветку.
4. Определи базу: по умолчанию текущий HEAD; если пользователь указал другую базу, проверь, что Git может однозначно разрешить её в коммит. При недоступной или неоднозначной базе сообщи причину, не заменяя её текущим HEAD.
5. Создай ветку с переключением через `git switch --no-track -c <name> <base>`, передав разрешённую базу как начальную точку. `--no-track` предотвращает наследование upstream, в частности ошибочную привязку новой ветки к `origin/main` при старте от remote-tracking ref. Первый push сможет установить upstream на ветку назначения. Наличие незакоммиченных изменений само по себе не препятствует операции; не делай автоматически commit или stash ради переключения.
6. Проверь имя активной ветки, фактическую базу и отсутствие upstream. Сообщи имя ветки и хеш коммита базы.

Если Git не позволяет создать ветку или переключиться на неё, сообщи причину. Не применяй принудительное переключение или сброс изменений.
