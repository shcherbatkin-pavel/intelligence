# Создание коммита

Перед созданием коммита прочитай
[references/conventionalcommits.md](references/conventionalcommits.md),
открой указанную там документацию и примени полученные знания
при составлении сообщения коммита.

## Порядок работы

1. Проверь `git status`, изменения в индексе и рабочем дереве, а также содержимое новых файлов, которые планируешь включить. Определи состав коммита по запросу пользователя и контексту задачи.
2. Добавь в индекс относящиеся к задаче изменения. Учитывай уже подготовленные изменения: обычный `git commit` включает всё содержимое индекса. Не включай посторонние изменения и не убирай их из индекса без необходимости; если состав коммита неоднозначен и контекст не помогает, уточни его у пользователя.
3. Проверь итоговый diff в индексе и составь сообщение по фактическому содержимому коммита. Соблюдай Conventional Commits; язык описания и дополнительные соглашения выбирай по инструкциям репозитория и истории коммитов. Scope необязателен, если проект не требует его.
4. Создай коммит и проверь результат. Если подходящих изменений нет, сообщи об этом без создания пустого коммита.
5. Сообщи хеш и сообщение созданного коммита, а также оставшиеся незакоммиченные изменения, если они есть.

Amend, обход hooks и push выполняй только по соответствующему запросу или уже имеющейся договорённости. При ошибке сообщи причину; не выдавай неуспешную попытку за созданный коммит.
