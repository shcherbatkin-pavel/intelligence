# Отправка Git-ветки

1. Проверь текущую ветку, `git status`, remotes и upstream. При detached HEAD остановись и сообщи причину. Незакоммиченные изменения не входят в push; не создавай ради него коммит или stash.
2. Определи назначение: явные remote и целевая ветка пользователя имеют приоритет; иначе используй upstream текущей ветки. Если upstream отсутствует, используй `origin` и одноимённую ветку. Если назначение отсутствует или неоднозначно, уточни его, не добавляя remote автоматически.
3. Проверь коммиты, которые будут отправлены, относительно целевой ветки. При необходимости обнови сведения о ней через fetch. Если удалённой ветки ещё нет, проверь историю относительно известной базы. Если отправка захватывает явно постороннюю работу, уточни состав до push.
4. Отправь только текущую ветку с явным назначением: `git push <remote> HEAD:refs/heads/<target>`. При первой отправке добавь `--set-upstream`; существующий upstream не меняй без запроса. Не используй `--all`, `--mirror`, отправку тегов или force push.
5. Проверь, что удалённая ветка указывает на отправленный HEAD, например через `git ls-remote --heads`. Сообщи локальную ветку, remote, целевую ветку и хеш отправленного коммита. Если подходящие коммиты уже отправлены, сообщи об этом как об успешном результате без новой отправки.

При отклонении push или ошибке проверки сообщи причину и фактическое состояние. Не выполняй автоматически pull, merge, rebase или reset. Если результат сетевой операции неизвестен, проверь удалённую ветку перед повторной попыткой. PR этот скил не создаёт.
